# 美心 AI 行政助手开发路线

路线按“尽快形成可上线闭环”排序。每阶段只在完成标准和测试证据满足后进入下一阶段；实际日期由人员投入和业务确认决定，不用虚假的固定工期替代验收。

## 阶段 1：基础系统框架（当前阶段）

### 开发内容

- 建立项目规范、系统设计、数据库设计和路线文档。
- 搭建 FastAPI 单体、Jinja2 页面、配置管理、结构化日志和健康检查。
- 建立 SQLAlchemy/Alembic、PostgreSQL/SQLite 环境策略。
- 建立 pytest、代码质量检查、`.env.example`、Docker Compose 和启动说明。
- 确认真实 Excel 样例、课消规则、计薪规则与权限细节。

### 完成标准

- 新开发者按 README 可启动应用并看到中文首页。
- `/health/live` 返回存活状态，`/health/ready` 能识别数据库可用性。
- 测试可运行；仓库不含密钥和真实个人数据。
- 技术方案及核心表结构通过业务负责人评审。

### 测试方法

- 自动测试应用启动、首页和健康检查。
- 在 SQLite 开发配置及 PostgreSQL 容器各启动一次。
- 从全新环境按文档执行安装，核查环境变量缺失时提示。

### 上线方式

本阶段只部署内部测试环境，不录入真实业务数据；使用 Docker Compose 或单机进程验证网络、日志、备份目录和 HTTPS 入口。

## 阶段 2：学生 + 课程管理 + Excel 导入

### 开发内容

- 用户登录、角色权限和审计基础。
- 学生、家长、教师、课程、选课和课时账户管理。
- 学生/课程/教师 Excel 模板、上传、校验预览、确认导入、错误报告。
- 搜索、状态筛选、详情页和受控导出。

### 完成标准

- 行政可在不接触数据库的情况下导入并维护约 50 名学生。
- 重复编号、缺失必填项和错误格式能在写入前发现；重复导入不重复建档。
- 教师只能看到授权范围，行政与负责人权限符合设计。

### 测试方法

- 使用脱敏样例覆盖新增、更新、跳过、错误、中文表头和重复文件。
- 权限矩阵自动测试；核心 CRUD、搜索和状态变更集成测试。
- 邀请至少一名行政人员按任务清单完成可用性验收。

### 上线方式

先备份现有 Excel，在测试环境演练导入并由负责人核对数量和抽样记录；再在生产空库导入，保留原文件与结果报告。

## 阶段 3：排课 + 签到 + 自动课消

### 开发内容

- 日/周课表、单次与批量排课、教师/学生/教室冲突检查。
- 教师签到、行政复核、签到修改审计。
- 按确认签到自动生成课消，余额不足提示、幂等、防重、撤销冲正和对账。

### 完成标准

- 从排课到签到确认、课消、余额展示形成完整闭环。
- 重复点击或并发请求不会重复扣课；撤销可追溯且余额正确。
- 课消失败不会留下半条记录，异常清楚显示给行政。

### 测试方法

- 覆盖到课、迟到、请假、缺勤、补课、余额不足、重复确认、并发确认、撤销和冲正。
- 用测试周课表进行端到端演练；逐账户核对流水和余额汇总。
- 生产影子运行一周，与人工 Excel 结果逐日对账后再切换。

### 上线方式

先只读排课与双轨记账，再启用自动课消；每日导出对账，确认稳定后停止原人工扣减方式，但保留应急表单和恢复流程。

## 阶段 4：缴费和剩余课时提醒

### 开发内容

- 缴费草稿、确认、作废/退款及收据号管理。
- 课时购买入账、低余额规则、续费候选和提醒处理状态。
- 缴费与余额查询、期间汇总和导出。

### 完成标准

- 每笔确认缴费只入账一次，可从余额追溯到缴费记录。
- 低于阈值的学生按课程准确提醒，已处理提醒不反复骚扰。
- 作废/退款采用冲正并保留完整历史。

### 测试方法

- 金额与课时精度、重复收据号、重复确认、退款、作废和权限测试。
- 用历史脱敏账目抽样回放，与人工结果核对。
- 负责人逐笔验收一个完整结算周期。

### 上线方式

初期由行政登记、负责人确认；双轨核对一个周期。开启每日备份和月度恢复演练后再作为主台账。

## 阶段 5：教师课时统计与工资基础计算

### 开发内容

- 计薪规则版本、已完成课次生成教师课时、调整与确认。
- 结算批次、工资基础明细、复核锁定、Excel 导出。
- 课时异常和历史差异展示。

### 完成标准

- 每个完成课次最多生成一条有效教师课时记录。
- 历史规则变化不改变已确认结果；锁定批次不可静默修改。
- 教师仅可查看本人统计，负责人可查看并审核全部。

### 测试方法

- 覆盖按次、按小时或最终确认的实际规则、跨月课程、取消课程、调整、重复课次和规则生效边界。
- 与至少两个历史工资周期人工表格逐项比对。

### 上线方式

并行计算两个结算周期；负责人签字确认差异解释后，系统结果作为工资基础数据，最终发放仍走现有财务审批。

## 阶段 6：AI 日报与异常分析

### 开发内容

- 确定性日报指标、漏签到/低余额/异常缺勤/教师课时波动规则。
- 可选大模型摘要、超时降级模板、证据链接、提示词版本和生成审计。
- 日报页面与处理闭环；是否发送微信在合规和接口确认后另行决定。

### 完成标准

- 不配置或调用失败时仍能生成基于规则的日报。
- 每个数字和异常可点击追溯；AI 不可写入课消、缴费或工资事实表。
- 对测试数据不虚构事实，敏感数据最小化发送。

### 测试方法

- 固定数据集的指标快照测试、异常规则边界测试、模型超时/限流/错误降级测试。
- 人工评审至少 14 天日报，记录误报和漏报并调阈值。

### 上线方式

先仅负责人可见，随后开放行政查看；未完成隐私评审前不把姓名、手机号等直接发送给外部模型。

## 阶段 7：排课智能辅助

### 开发内容

- 基于教师可用时间、学生需求、教室容量和冲突的候选排课。
- 规则求解优先，AI 用于解释建议和处理自然语言偏好；最终由行政确认。
- 方案比较、冲突原因和手工调整。

### 完成标准

- 系统只生成候选，不擅自发布课表；硬约束零冲突。
- 行政能理解每个建议原因并快速修改。
- 建议相较纯人工确实减少时间，否则不强行上线。

### 测试方法

- 使用脱敏历史周课表回放，验证硬约束、无解提示和稳定性。
- 记录行政完成同类排课的耗时、修改次数和满意度。

### 上线方式

先作为可选“生成建议”功能灰度给一名行政使用；连续数周达标后再推广，始终保留手工排课。

## 第一阶段剩余决策清单

1. 获取脱敏学生、课程、教师 Excel 样例及当前工资统计表。
2. 确认签到状态与扣课规则、余额不足策略、退款/转课规则。
3. 确认教师计薪方法和历史规则生效方式。
4. 确认部署地点、域名/HTTPS、备份负责人和可接受停机窗口。
5. 调查“校精灵”可用的 Excel 导出字段或正式 API 文档。
